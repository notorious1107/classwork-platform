# 方格数学 · 班级作业空间

一个可实际运行的单班级数学作业系统。React 前端通过 HTTP API 调用 Express 单体后端；账号、登录会话、班级名单、题目、草稿、正式答卷和成绩保存在 SQLite 文件中。批改完全使用确定的数学规则，不调用 AI 或外部服务。

## 1. 启动体验

需要 **Node.js 22.13 或更高版本**、npm 和现代浏览器。本次开发环境为 Windows / Node.js 22.17.0。

在这个项目目录打开 PowerShell：

```powershell
npm ci
npm run dev
```

打开 **[http://localhost:5173](http://localhost:5173)**。保持命令窗口运行；按 `Ctrl+C` 停止。

Windows 也可以双击项目里的 **start-dev.cmd**，缺少依赖时会先安装。

- 前端：`http://localhost:5173`。
- 后端健康检查：`http://localhost:3001/api/health`。
- 首次启动自动建表、初始化演示数据；再次启动不会重置或重复导入。
- 所有界面资源和出题、批改均在本机运行；安装依赖和首次下载测试浏览器需要联网。

如果 PowerShell 提示“不允许运行 npm.ps1”，把上面命令里的 `npm` 换为 `npm.cmd`，不需要修改系统执行策略。

## 2. 主要入口与体验顺序

### 教师

1. 登录后进入「班级作业」：查看作业列表、进行中的作业数和已提交平均分。
2. 「班级学生」：创建学生账号，指定姓名、账号、初始密码；也能重置学生密码。
3. 「发布作业」：输入名称，选择一个或多个知识点、10 / 20 / 50 道题和截止时间，点击「生成并发布作业」。
4. 作业卡片「查看作业」：查看已提交、未提交人数和平均分，也能查看全部题目及正确答案。
5. 学生列表中「查看答卷 / 查看草稿」：查看该学生逐题答案、正确答案和评分；草稿明确标为未提交、未批改。

### 学生

1. 登录后进入「我的作业」，查看截止时间和待完成 / 草稿 / 已提交 / 已截止状态。
2. 「开始作答 / 继续作答」：逐题输入，回车跳到下一题。
3. 停止输入约 1.2 秒会自动保存，也可以点击「保存草稿」。**看到“已保存”才表示数据库保存成功。**
4. 返回作业列表或退出登录时会先保存；有未保存内容时关闭或刷新页面，浏览器会提示。网络失败时保留当前页面答案并显示错误，可以重试。
5. 「正式提交」会先显示确认框，提醒未填写的题量。确认后自动批改，展示分数和错题的本人答案、正确答案。
6. 下次登录仍可查看已提交的答卷和成绩。

如果其他标签页退出或切换了账号，答题页会停止保存并提示身份变化。选择「在新页面重新登录」，使用原账号登录，再回到原答题页保存，未保存答案仍在原页。保存失败时点退出，会明确询问是否丢弃未保存修改，不会无限卡在退出按钮上。

两种身份都可点击姓名旁的钥匙图标修改自己的密码，点击「退出登录」退出。

## 3. 已采用的业务规则

- 固定一个班级、一个初始教师；教师创建学生，不开放公开注册。
- 发布时固定本班学生名单；后来创建的学生从下一份新作业开始参与，旧作业的统计人数不变。
- 全班同一份作业使用相同题目。多个知识点尽量均分题量，同份作业不重复题目。
- **20 以内加减**：数值和结果在 0–20，减法无负数。
- **20 以内乘除**：因数、被除数、除数与结果在 1–20，乘积不超过 20，除法整除。
- **100 以内四则混合**：两步运算，含乘除与加减或括号；先括号、再乘除、后加减；结果为 0–100 的整数。
- 每份满分 100，每题等分；10 / 20 / 50 道题分别每题 10 / 5 / 2 分。空题和无效答案都算错，合法数字按数值比较（如 `03`、`3.0` 与 `3` 等价）。不执行学生输入的表达式。
- 草稿不算提交，不计分、不进入平均分。教师能查看已保存草稿。
- 正式提交一次后即锁定。提交与评分在同一个数据库事务内完成，不允许客户端指定分数或正确答案。
- 截止时间由服务器严格检查，截止后不可保存或提交，仍可查看已保存内容。截止前已提交的结果始终可查看。
- 作业名称、题目、题量、名单和截止时间发布后不可修改。第一版暂不提供撤回、补交、重做或删除。
- 时间在数据库中统一保存为 UTC；页面按设备本地时区显示。教师在中国使用时通常为北京时间。
- 学生在正式提交前无法从自己的 API 取得正确答案；学生不能查看教师页面或其他学生的答卷。
- 两个标签页同时修改草稿时，用版本号阻止旧页面覆盖新草稿。遇到版本冲突，请先记录本页尚未保存的修改，再刷新获取最新草稿。

## 4. 数据保存与生产方式运行

默认数据库位于 `data/classwork.sqlite`。运行时可能同时出现 `-wal` 和 `-shm` 文件，这是 SQLite 的正常工作文件。

**不要删除 `data` 目录来“重新启动”。** 停止服务后再次启动即可继续使用。备份时先停止服务，再复制整个 `data` 目录；恢复时也先停止服务。

如果不需要开发时自动刷新，可以先构建，再用一个后端进程同时提供前端静态文件和 API：

```powershell
npm run build
npm start
```

打开 **[http://localhost:3001](http://localhost:3001)**。这仍然是前后端通过 API 分离的架构，部署时合并为同一个来源可以简化 Cookie 和跨域配置。

### 使用空白数据库开始正式建班

先停止服务，复制 `.env.example` 为 `.env`，使用另一个数据库路径，并修改以下值：

```dotenv
DATABASE_PATH=./data/classroom-real.sqlite
SEED_DEMO=false
TEACHER_USERNAME=math_teacher
TEACHER_PASSWORD=请替换为至少8位的自定强密码
TEACHER_NAME=张老师
CLASS_NAME=三年级（1）班
COOKIE_SECURE=false
```

随后运行 `npm run dev` 或 `npm run build`、`npm start`。系统只初始化你指定的教师和班级，不导入演示学生或作业；先创建学生，再发布第一份作业。原演示数据库保持原样。

这些初始化变量**只对新数据库生效**，不会覆盖已有账号、班级或密码。已有账号请在界面修改密码或由教师重置学生密码。

### 给其他设备使用

开发模式监听 `0.0.0.0`，同一局域网的设备可以通过终端打印的 Network 地址访问 `5173`，例如 `http://电脑的局域网IP:5173`；电脑必须保持运行且系统防火墙允许访问。使用生产方式时访问电脑 IP 的 `3001` 端口。

本次未配置公网域名、HTTPS、服务器托管或系统防火墙，也未在真实手机或其他电脑上连接验证。真正对外提供服务时，需要在服务器运行生产构建，使用 HTTPS 反向代理，将 `COOKIE_SECURE=true`，使用正式账号并安排数据库备份。仅修改该变量不会自动开启 HTTPS。

## 5. 检查与测试

```powershell
npm run check         # 前后端 TypeScript 检查
npm test              # 数学规则、API 权限、保存、评分与数据库恢复测试
npm run build         # 生产构建
npx playwright install chromium  # 首次运行浏览器测试前执行
npm run test:e2e      # 自动构建后，使用独立数据库运行真实 Chromium 测试
npm run test:restart  # 自动构建后，真正停止并重新启动后端进程，验证数据持久性
```

测试只写入内存、临时目录或已忽略的 `test-results` 目录，不修改你的演示 / 正式数据库。浏览器测试使用 `3101`，进程重启测试使用 `3102`，开发服务使用 `5173` 与 `3001`。

验证细节与范围见 [docs/verification.md](docs/verification.md)。数据表、API 和代码位置见 [docs/architecture.md](docs/architecture.md)。

2026-10-19 已通过 20 项 Chromium 端到端测试、16 项后端与数学测试，并进行了浏览器 GUI 点击验收；本次发现及修复见 [GUI 验收报告](docs/gui-audit-2026-10-19.md)。

## 6. 常见情况

- **端口被占用**：先停止之前开启的项目窗口，或关闭占用 `5173` / `3001` 的服务。不要同时启动两个开发实例。
- **生产打开页面为空或 404**：先成功执行 `npm run build`，再执行 `npm start`，并确保当前目录是项目根目录。
- **登录提示无法连接服务器**：检查运行窗口是否退出。开发方式必须同时运行前后端，推荐直接使用 `npm run dev`。
- **账号或密码不正确**：核对大小写和演示密码；若连接的是正式数据库，使用 `.env` 中首次初始化的账号，而不是演示账号。
- **SQLite ExperimentalWarning**：当前 Node.js 22.17.0 对内置 SQLite 发出实验功能提示，本次全部测试和生产构建均可运行，不是启动失败。项目依赖该 Node 内置模块，换用旧 Node 20 会失败。
- **重启后作业已截止**：截止时间保留原值，不会随着重启自动延长。请由教师发布一份新作业。
- **断网时关闭页面**：尚未成功上传的修改无法保证保存。请恢复连接并确认“草稿已保存”后离开；第一版没有离线作答同步。

第一版的目标是把一个班级的核心闭环做好，暂未实现多班级、公开注册、邮件找回密码、人工改分、成绩导出、作业撤回和题库编辑。
