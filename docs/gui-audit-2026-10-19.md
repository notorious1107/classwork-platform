# GUI 与端到端验收报告

验证日期：2026-10-19，北京时间。环境：Windows、Node.js 22.17.0、本地 Express + Vite、浏览器 GUI 与 Playwright Chromium。原数据库未用于测试写入；GUI 使用 `data/gui-qa-*.sqlite`，自动化使用 `test-results/browser-*.sqlite`。

## 本次发现与修复

| 问题                     | 复现与原因                                                                                                    | 修复与回归证据                                                                                                                                  |
| ------------------------ | ------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| 登录失效后无法退出       | GUI 中一页答题、另一页退出，再回原页输入。保存返回 401；退出也先保存，导致一直被拒绝，没有可继续的路径。      | 保存失败后保留输入；提供新页面重新登录入口，以及明确的「留在本页 / 仍然退出」确认。GUI 已重走“保留 → 原账号重新登录 → 返回保存”，回归测试通过。 |
| 旧标签页可向新账号写答案 | 新增回归测试在 A 的答题页保留旧状态，另一页登录 B。原实现仅根据共享 Cookie 判定身份，会把旧页的答案保存到 B。 | 页面发送身份一致性头，服务器拒绝与 Cookie 身份不一致的请求。测试确认 B 没有生成草稿；重新登录 A 后能把原页答案保存给 A。                        |
| 草稿已保存却误报失败     | 模拟服务器已接受 PUT，但返回响应被丢弃。原实现保留旧版本号，继续保存会再遇到冲突。                            | 失败后读取服务器草稿；答案完全一致才同步版本并确认保存。测试包括首题带空格、继续填写下一题和刷新恢复。                                          |
| 作业已提交却卡在确认框   | 模拟 POST 已成功并评分，返回响应丢失。原实现仍显示提交失败，再试又提示已提交。                                | 读取已提交状态，自动进入已有批改结果。测试确认结果为 10 分、9 道空题均计错。                                                                    |
| 教师手机页面横向溢出     | GUI 视口 390 像素，学生页整页滚动宽度为 485。表格中的辅助文字使用绝对定位，其定位范围超出表格滚动容器。       | 给表格滚动容器建立定位范围。GUI 复查页面宽度 375（扣除滚动条）小于视口 390；表格仍可单独横向滚动。对应手机测试先失败、修复后通过。              |

前四项异常测试均先在旧实现运行失败，修复后通过；手机溢出也由 GUI 和自动化同时复现。另修正了测试中对「发布作业」链接的模糊定位：明确选择主导航，避免页面加载速度不同导致匹配到两个同名入口。这是测试稳定性修正，不计入产品缺陷数量。

## GUI 实际点击记录

1. 输入错误密码、检查错误提示、改用正确教师账号登录。
2. 学生姓名与账号搜索；检查无匹配结果、恢复完整列表。
3. 打开创建学生弹窗；重复账号被拒绝；改为隔离测试账号后创建成功。
4. 打开发布页；取消全部知识点时按钮禁用；过去截止时间被拒绝；选择乘除、10 道题和未来时间后发布成功。
5. 教师查看题目与答案、学生名单及初始统计。
6. 新学生登录，仅看到其加入后发布的作业；逐题填写，按回车跳题，手动保存，刷新后恢复答案。
7. 打开提交确认，看到空题提醒；取消并继续填写；全部填写正确后提交，显示 100 分、无错题。
8. 教师筛选已提交名单，确认 1 人已交、3 人未交、平均分 100；打开答卷，检查“只看错题”的空结果。
9. 打开并取消修改密码弹窗；实际改密与教师重置由下述独立自动化账户验证，没有改动原教师或学生密码。
10. 双标签页退出后在旧答题页输入，复现无法退出；修复后选择保留答案，在新页面登录原账号，再回原页保存成功。
11. 390 × 844 视口检查教师学生页和创建弹窗；复现并复查整页横向溢出。

## 自动化覆盖

| 文件                            | 数量 | 重点                                                                                                                                    |
| ------------------------------- | ---: | --------------------------------------------------------------------------------------------------------------------------------------- |
| `e2e/classroom.spec.ts`         |    4 | 教师建号与发布、学生草稿和提交、90 分错题、统计、50 题移动端、断网重试、标签页版本冲突、退出前保存                                      |
| `e2e/forms-and-results.spec.ts` |   11 | 登录与角色、重复账号及搜索、新生名单快照、10/20/50 题界面发布、0/100 分与教师筛选、截止只读、密码修改和重置、列表失败重试、教师手机表单 |
| `e2e/recovery.spec.ts`          |    5 | 会话失效的重新登录与明确退出、跨账号防误写、草稿响应丢失、提交响应丢失                                                                  |
| `server/tests/`                 |   16 | 数学属性检查、API 权限与身份一致性、保存、批改、截止、账号和文件持久化                                                                  |

通过命令：`npm run check`、`npm test`、`npm run test:e2e`，生产构建由端到端命令执行。进程重启检查使用 `node scripts/restart-smoke.mjs`。

密码测试只创建并操作一次性隔离账号。截止状态通过严格限定到测试目录的 fixture 设置，然后从浏览器验证，没有向正式 API 添加测试后门。网络异常由测试浏览器的路由拦截模拟，不修改应用正常网络配置。

## 仍然存在的范围限制

- 仅验证本机 GUI 和 Chromium，包括手机尺寸模拟；未使用真实手机、其他电脑、Safari 或 Firefox。
- 未做大量并发、断电、磁盘满等故障测试，也未配置公网 HTTPS 或运行独立安全审计。
- 尚未上传成功的答案仍只存在原答题页内存里。重新登录恢复需要保留原页；关闭原页或明确选择「仍然退出」后，这部分修改无法恢复。第一版仍不提供离线同步。
- 多班级、撤回作业、修改截止时间、成绩导出等不在本轮补测和实现范围内。
